# Nota técnica de versión

## Easygest - Versión inicial 1.0
La versión actual de Easygest corresponde al cierre técnico inicial del proyecto desarrollado durante la asignatura. Esta versión reúne los principales resultados obtenidos durante las etapas de análisis, diseño, modelado, arquitectura y gestión del proyecto.

## Contenido de la versión actual
La versión inicial incluye la definición de los requisitos funcionales y no funcionales, historias de usuario, modelos UML, arquitectura por capas y documentación de la organización del sistema.

También incluye la organización de las tareas mediante GitHub Projects y el seguimiento de funcionalidades y actividades técnicas mediante GitHub Issues.

El repositorio contiene además la documentación general de Easygest, la explicación de su organización en frontend y backend y un registro de los principales cambios realizados durante el desarrollo.

## Cambios controlados
Durante el desarrollo se controlaron diferentes avances y modificaciones, entre ellos:

- Definición y validación de los requisitos del sistema.
- Elaboración y organización de los modelos UML.
- Selección y documentación de la arquitectura por capas.
- Organización y seguimiento de las tareas mediante GitHub Projects.
- Consolidación de la documentación técnica dentro del repositorio de GitHub.

Estos cambios permiten mantener un registro organizado de la evolución del proyecto y conocer el estado de las diferentes actividades.

## Aspectos pendientes
Aunque se ha completado la documentación y el diseño inicial, todavía quedan pendientes actividades relacionadas con la implementación completa de las funcionalidades del sistema.

Entre los principales aspectos pendientes se encuentran el desarrollo de las interfaces, implementación de la lógica de negocio, conexión con la base de datos, integración entre frontend y backend, pruebas funcionales y validación final del sistema.

También permanecen funcionalidades en seguimiento dentro de GitHub Issues y GitHub Projects.

## Próximo paso técnico
El próximo paso técnico sería iniciar la implementación de Easygest tomando como base los requisitos, modelos UML y arquitectura definidos.

Se recomienda comenzar con la estructura de la base de datos y el backend, para posteriormente desarrollar las interfaces del frontend e integrar ambas partes. Después de la implementación se realizarían pruebas para comprobar el correcto funcionamiento del sistema y realizar los ajustes necesarios.
