# Registro de cambios y avances de Easygest
Durante el desarrollo de Easygest se realizaron diferentes avances y ajustes con el propósito de mejorar la definición, organización y diseño del sistema.

## 1. Definición y validación de requisitos
Se identificaron y organizaron los requisitos funcionales y no funcionales del sistema. Esto permitió establecer con mayor claridad las funciones que Easygest debe ofrecer y las características de calidad que debe cumplir.

## 2. Elaboración de los modelos UML
Se desarrollaron diagramas de casos de uso, clases, secuencia y actividad utilizando Visual Paradigm Online. Estos modelos permitieron representar tanto la estructura como el comportamiento esperado del sistema.

## 3. Definición de la arquitectura por capas
Se seleccionó una arquitectura por capas para organizar los componentes de Easygest según sus responsabilidades. Se establecieron elementos relacionados con la presentación, lógica de negocio, servicios, acceso a datos y almacenamiento de información.

## 4. Organización y seguimiento de tareas
Se utilizó GitHub Projects para organizar las actividades del proyecto mediante un tablero Kanban. Las tareas fueron clasificadas por prioridad, responsable, fecha estimada y estado, facilitando el seguimiento del avance.

## 5. Consolidación de la documentación técnica
Se organizó el repositorio de GitHub con la documentación principal del proyecto, incluyendo requisitos, modelos UML, arquitectura y gestión del avance. También se actualizó el README con información general del sistema y su organización en frontend y backend.
